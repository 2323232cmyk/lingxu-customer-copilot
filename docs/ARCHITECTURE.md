# 桌面架构与开发

## 数据流

用户选择本机账号和会话 → 只读读取与规范化 → 当前聊天、授权 CRM 资料和知识检索 → 远程模型调用确认 → 可编辑建议 → 人工核对并复制发送。

当前桌面应用没有自动消息发送器，Android 和视频号的实现不在本仓库。

## 进程和源码

- `src/main.ts`、`src/main/`：文件、网络、凭据、读取任务和导出；`src/preload.ts` 暴露类型化 IPC。
- `src/app/`：工作台、会话、CRM、设置、布局与草稿；新上下文不直接销毁正在编辑的草稿。
- `src/shared/`：接口、回复策略、消息次序及导出约定。
- 微信和语音任务在独立 utility process 运行；渲染进程不直接接触本机数据库或密钥。

窗口禁用 Node integration，启用 context isolation、sandbox 和 navigation/IPC 来源检查。资料、账号或设置变化使原预览失效；取消和迟到结果均需处理。

## 集成

CRM 为已有协议的只读客户端适配，不随本仓库提供服务端。默认知识库使用本地资料。可选云端知识适配保留在源码中，但服务地址已替换为保留域名，默认不启用，不能用示例端点访问真实公司数据。

使用者自行配置模型，支持兼容 OpenAI 的接口及本机服务。远程调用展示数据范围并确认；本机存储使用操作系统加密能力，仓库不包含任何可用密钥。

本机微信读取依赖版本相关的结构和用户授权，并非官方开放接口。兼容性、平台要求和账号风险需自行评估；不将固定版本测试推断为所有版本可用。

## 原生资源和构建

锁定依赖与资源清单保留版本、大小、SHA-256。`native:download` 只准备公开 SQLite DLL；`native:prepare` 从 npm 准备 Koffi；`native:verify` 校验内容。离线语音模型在使用者确认许可后另行下载。

源构建和 UI 预备检查不启动真实业务。原生资源、应用安装、真实服务和实际消息读取需分别验证。公开版默认使用独立用户目录与安装标识，自动更新关闭。
